## 三、⚠️ P1：候选池的「∪ 核心池」是空操作

线上实测：

```
涨停池 = 首板 33 + 连板 7 = 40
核心池 cores = 7 只（sz000993 闽东电力 …）
cores == 连板池（完全相等），且 ⊆ 涨停池
→ union(涨停, 核心池) = 40 = scan_n   ✅ 算术上被证伪了「核心池有增量」的假设
```

**后果（这是本模块最本质的短板）**：
候选池只有涨停股 ⇒ **所有「突破」信号必然同时是当日涨停股**。形态无法在涨停之前发现任何标的，
它退化成了「涨停股的二次筛选器」，而不是「突破的前置发现器」。
一个"粘合突破"形态最有价值的时刻恰恰是**突破当日、但还没封板**——现在这个时刻被池子直接排除了。

**建议**（按性价比排序）：
1. 池子加入**放量异动但未涨停**的票（如：收盘站上 MA21 + 涨幅 3~9% + 量比 ≥2）；
2. 或扫**中证2000/成交额前 300** 这类可控范围，直接抓"尚未涨停的粘合突破"；
3. 至少把「核心池」换成「近 3 日在池」的历史核心，让并集真正产生增量。

## 四、信号有效性回放（15 个交易日 / 827 样本）

口径：D 日复算形态 → **实操收益 = D+2 收盘 / D+1 开盘 − 1**（T+1 买、T+2 卖，与项目 `pct_real` 一致）。

| 分组 | 样本 | 实操均值 | 中位 | 胜率 | 理论均值(次日收盘) |
|---|---|---|---|---|---|
| **突破** | 78 | **+0.43%** | −0.58% | 44.9% | +1.73% |
| 粘合中 | 112 | −0.02% | −1.33% | 39.3% | +1.59% |
| 池内全体（基准） | 827 | **−0.14%** | −0.82% | 44.9% | +1.45% |

**读法（诚实版）**：
- **基准本身是负的（−0.14%）** —— "涨停次日开盘买"的期望收益为负，与项目已有的"高潮不接力"完全吻合；
- 突破组转正（+0.43%），**相对增量 +0.57pp**；
- 但 **Welch t = 0.75**（SE=0.76pp）→ **不显著，不能认定形态有真实 alpha**；
- **三组中位数全为负**，说明收益靠少数大赢家拉起（右偏），**稳定性差**；
- 突破组胜率 44.9%，**不到一半**。

### 放量确认到底有没有用？

| 分组 | 样本 | 实操均值 | 中位 | 胜率 |
|---|---|---|---|---|
| 突破 + 放量 | 62 | +0.72% | −0.63% | **41.9%** |
| 突破 + 未放量 | 16 | −0.70% | +0.42% | 56.2% |
| 基准 | 827 | −0.14% | −0.82% | 44.9% |

放量组**均值更高但胜率更低**——典型的"放量 = 波动放大"，均值靠尾部大赢家。
当前把 `vol_ok` 只当"确认旗标"、不参与判定，**这个取舍是对的**（若改成硬门槛，样本会砍到 62 且胜率更差）。

## 五、⚠️ P2：前端「冰点」是死代码

`web/src/views/Pattern.vue:10`
```js
const ebbHint = computed(() => stage.value === '退潮' || stage.value === '冰点')
```
但 `quant/regime/cycle.py` 的 stage 取值只有 **启动 / 发酵 / 高潮 / 震荡 / 退潮**，永远不等于 `'冰点'`。
而真正承载"冰点"信息的是 `sentiment.band`（线上实测 = **`冰点-退潮`**），前端**完全没读它**。

后果：`stage=震荡` 而 `band=冰点-退潮` 的日子不会出提示条（今天 stage 恰好是退潮，所以看得到，掩盖了这个问题）。

**建议**：
```js
const band = computed(() => (s.sentiment && s.sentiment.band) || '')
const ebbHint = computed(() => stage.value === '退潮' || band.value.includes('冰点'))
```

## 六、⚠️ P3：不校验 K 线最新日，存在静默陈旧风险

`ma_pattern.scan_one` 直接取 `rows[-1]` 当作"今天"，并且 `snapshot.py:511` 把 `pat["date"]` 覆写成快照的 `today`：

```python
pat = scan_pattern(list(_cmap.values()))
pat["date"] = today          # ← 覆盖，掩盖了每行自带的行级 date
```

单行里保留的 `date` 字段前端**从不展示**（页面只显示 `s.date`）。所以若：
- 某只票当日停牌 / 腾讯数据延迟 → 用**旧 bar** 计算，可能产出假"突破"；
- 16:05 任务跑时腾讯当日日K尚未落库 → 整个池子会静默算在**昨日**上，而页面仍显示今天。

今日实测无此问题（15/15 行 `last_bar` 均 = 09-11），但这是**纯靠运气**。

**建议**（成本极低）：
```python
if rows[-1]["date"] != expected_date:   # expected_date 由调用方传入 today
    return None                          # 或记入 stale 计数并在快照里暴露
```
并在 `scan_pattern` 返回值里加 `stale_n`，前端 >0 时给黄色提示。

## 七、轻微问题（P6）

1. **`watch[:30]` 截断与 `watch_n` 不一致** —— 若粘合票 >30，页面显示 `watch_n=57` 但只列 30 条，用户会以为丢数据。今日 9 条未触发。建议返回 `watch_truncated: true` 或直接改为"显示前 N / 共 M"。
2. **`run_at` 重复计算** —— `glue_days` 与 `state` 判定各调一次，纯性能小事（当前 725ms 无压力）。
3. **`_cmap` 未过滤空 code** —— 若 `normalize_code` 返回 `""`，会占用一个 `scan_n` 名额但不产出任何信号（`scan_one` 直接 return None）。建议加 `if not c: continue`。
4. **`kline.py:_http` 在 SSL 失败时降级为不校验证书**（`_CTX_INSECURE`）——沙箱环境下的必要妥协，但等于对腾讯/新浪的中间人攻击零防护，且**静默发生**。建议加环境变量开关 + 日志，别在生产路径上默认开启。
5. **`粘合中` 列表无操作价值** —— 112 样本实操 −0.02%、胜率 39.3%（全组最低）。UI 已有"观察"字样，建议补一句"不建议据此建仓"。

## 九、一句话总结

> **引擎算得对、数据是新的、部署是同步的——问题不在实现，在定位。**
> 当前它只能看到"已经涨停的粘合突破"，且相对涨停池基准的增量在统计上不显著（t=0.75）。
> 它**可以作为排序权重和过滤条件**（情绪中等区间 +1.27%/胜率 59.1% 有方向性价值），
> 但**不能当入场信号**。要让它真正产生价值，第一步是把候选池从"涨停池"放开到"即将突破"。
