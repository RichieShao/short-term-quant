# 个人短线量化 · short-term-quant

基于**舒九《个人关于投机的理解与做法》**方法论搭建的个人 A 股短线量化系统。
覆盖「盘后数据抓取 → 周期定位 → 核心识别 → 情绪/质地体检 → 形态扫描 → 前端复盘」完整链路，
云端定时任务驱动，手机端直接看盘。

> ⚠️ **免责声明**：本项目是个人研究/自律工具，不构成任何投资建议。
> 所有评分、分档、周期标签均为**离线统计口径**，不保证前瞻有效性。
> 短线交易风险极高，请独立判断、自负盈亏。

---

## 一、核心公式

```
收益 = 核心识别 × 周期定位 × 仓位管理 × 监管风控
```

四个因子不是加权求和而是**乘法**——任一为 0，整体归零。系统据此把「找票」和「择时」拆成两条独立管线，
再在体检页做交叉。

## 三、Lab 体检引擎（`quant/report/lab.py`）

系统里唯一做「质地 × 情绪」交叉的模块，五道闸门：

| 闸门 | 作用 | 口径 |
|---|---|---|
| **G1 排雷** | 一票否决 | ST / 质押 ≥50% / 商誉 ≥100% |
| **G2 质地 Q** | 打分 | 规模 40 + 盈利 35 + 估值 25 |
| **G3 情绪 E** | 打分 | 连板基准 + 核心 AB + 10 − verb 风控 |
| **G4 融合** | `Lab = Q×0.30 + E×0.70` | 权重经网格标定（E 主导单调更优） |
| **G5 排序** | 榜单 | verb（风险否决）优先级高于 Lab 分 |

**周期感知的 E**：`启动 +6 / 发酵 +3 / 高潮 板高×(−5) / 退潮 −16`，
周期 stage 取自当日快照 `cyc.stage`，缺失时按 6 日窗口懒算。

**已知边界（诚实标注）**：
- 权重 0.30/0.70 的复算样本仍偏少（目标 ≥30 交易日），当前阶段属于**弱校准**；
- 261 个交易日里「退潮」仅 3 天 → `−16` 属启发式，从未被充分校准，退潮期 Lab 分会整体塌陷，
  应理解为「整体不建议参与」而非「便宜机会」。

## 四、形态模块：双线粘合突破 MA7/MA21

| 项 | 口径 |
|---|---|
| 粘合 | `\|MA7 − MA21\| / MA21 ≤ 2.5%` 且**连续 ≥3 日** |
| 突破 | 当日**收盘上穿 MA21** 且 **MA7 上翘** |
| 量能 | `成交量 ≥ 前5日均量 × 1.5`（**确认旗标**，不参与突破判定） |
| 数据 | 腾讯日K，**前复权 qfq** |
| 候选池 | **当日涨停 ∪ 核心池 ∪ 全市场异动池**（三源合并去重） |
| 新鲜度 | K线最后一根 ≠ 目标交易日的票**不产出信号**，只计入 `stale_n` |

### 候选池：为什么必须有第三源

早期候选池 = 当日涨停 ∪ 核心池，而**核心池 ⊆ 涨停池**（实测 cores(7) == 连板池(7) ⊆ 涨停池(40)），
`∪` 是空操作 ⇒ 所有"突破"必然是当日涨停股，形态退化为「涨停股二次筛选器」，
**丧失在涨停之前发现突破的能力**——而那正是粘合突破的全部价值。

现补入 **全市场异动池**（`quant/data/universe.py`）：从东财全市场列表筛出
「当日涨幅 ≥1% 且未涨停 且成交额 ≥1亿 且（量比 ≥1.2 或 换手 ≥3%）」，按量比取前 150 只。
实测（2026-09-11）：池子 40 → **190**，突破命中 6 → **17**，新增的 11 只**全部是非涨停的放量突破股**。

### 资金流与龙虎榜

- **资金流**（东财口径，**参与排序、不参与突破判定**）：当日主力净额 + 净占比、超大/大/中/小四档拆解、
  近 3/5 日累计、连续净流入天数。
  - 资金分 = 当日净占比 0.5 + 近3日累计 0.3 + 连续天数 0.2，各因子先做**池内百分位**；
    **缺失项自动剔除并重新归一**（`flow_parts` 透出实际参与因子数）。
  - 多日趋势三级来源：**① 自累积表 `flow_hist`（首选）→ ② 东财多日接口（已失效）→ ③ 新浪兜底**。
    ⚠ 东财 `push2his/.../fflow/daykline` 与新浪 `ssl_qsfx_zjlrqs` 都不稳定：
    前者**全平台失效**，后者大量并发会返回 **HTTP 456 反爬限流**。故趋势只对**有形态信号的票**
    按需拉取（`defer_sina` + `fill_trend`），并带限流短路。
- **龙虎榜**：当日榜（T）+ 前一交易日榜（T-1）**两者都存**；上榜标记 + 净买卖额、机构席位、席位明细、上榜原因。
  当日榜约 **18:00 后**才发布 ⇒ 16:05/16:40 快照里为空，由 **21:00 夜间补充任务**重算并只合并该字段。

### 资金性质「底色」（季报，`quant/data/holders.py`）

- **分类口径**（东财 F10 股东研究）：十大流通股东按 `HOLDER_TYPE` 分类为
  国家队 / 社保基金 / QFII / 险资 / 公募基金 / 私募 / 北向资金 / 产业资本 / 牛散（9 类）；
  另解析 `jgcc` 的 `ORG_TYPE`（`01`基金 `02`QFII `03`社保 `05`保险）得**全体机构口径** `org`。
  ⚠ 十大与全体机构是**两个分母，不能相加**；前端分别标注。
- **游资不在季报里**，由龙虎榜席位 `seat_kind()` 给 **T+0「席位性质」**（机构专用 / 北向专用 / 游资营业部），与季报底色互补。
- **H 股陷阱**：A+H 公司的 `香港中央结算(代理人)` / `HKSCC NOMINEES` 是 H 股名义持有人，
  **不是北向** —— 只有精确等于 `香港中央结算有限公司` 才计北向；H 股占比单列 `h_pct` 仅备注。
- **缓存与刷新**（`holder_cache` 集合，季报窗口）：`need_refresh` = 报告期早于
  `expected_report()`（按披露截止推算）**且** 距上次抓取 ≥7 天（防次新股天天白拉）。
  无 F10 数据的票（北交所等）写 `failed:1` 占位，同样吃 7 天防抖。
- **⚠ 架构红线**：一条画像记录 ~1KB，190 只 ≈180KB —— **超出嵌套 callFunction 响应上限
  （约 100-128KB），且静默截断不报错**（实测 179 条只回来 10 条）。故 `build_context`
  **只报缺口清单**（`holder_meta.need`），由 daily_job 分批（40 只/批 ≈40KB）调
  `action=holder_sync` 抓取写库，再用完整缓存重算一次形态。
- **附带数据**：股东户数（筹码集中度）、实际控制人（区分实控人与牛散）、
  近期持股变动（临时公告口径，比季报新）。
- 已知坑：东财 F10 仅沪深（`PC_HSF10` 不覆盖北交所）；`build()` 里 `jgcc` 循环变量
  曾遮蔽 `code` 变量导致全记录 `code=None`（已修，有回归单测）。

### 消息面定性「上涨逻辑」（T-1 + T，`quant/data/news.py`）

- **数据源**：东财 F10 资讯 `PC_HSF10/NewsBulletin/PageAjax`，一次请求同时返回
  `gsgg`（公告，`title`+`display_time` 真实挂网时间）与 `gszx.data.items`
  （相关新闻，`title`+`showDateTime` epoch 毫秒 UTC）。⚠ `notice_date` 是披露日
  （常写 T+1），**不能**用来判时点；`display_time` 毫秒段用冒号分隔需截断。
- **定性（4+1，宁缺勿滥）**：利好·公告（业绩预增/中标/并购/回购/增持等**公告**标题关键词；
  新闻不判利好防标题党污染）＞ 题材·共振（窗口内有相关新闻，取最新一条做代表）＞
  资金·独行（无消息，最"干净"的技术突破）＋ 静默兜底（接口失败/无数据）。
  **风险·警示**（减持/澄清/问询/预亏/质押…）优先级最高且**含 T 盘后**——宁可错杀。
- **时点**：`T-1盘后 / T-1盘中 / T盘中 / T盘后`（按挂网时间落槽）；T 15:00 收盘后的
  消息不影响 T 突破的定价，故不参与利好/题材定性（风险例外）。
- **覆盖与体量**：只抓**信号票**（突破+粘合观察 ≈75 只）；突破票带 3 条标题明细
  （~250B/票），粘合票只回标签（~80B/票），合计 ~10KB，远低于嵌套响应截断线。
  原始明细不落盘、不入快照文档。
- **不参与排序与突破判定**（与资金流同口径：只展示）。实测分布（2026-09-11）：
  题材·共振 37 / 资金·独行 31 / 风险·警示 4 / 利好·公告 2 / 静默 1。

> 扫描仅在「快照日 == 全局最新交易日」时执行，历史日不补算。
> 当日龙虎榜发布晚于收盘 ⇒ `cloudbaserc.json` 里 `daily_job` 挂了两个触发器：
> `daily_1605`（主流程）与 `night_2100`（只重算形态块再合并回当日文档）。

## 五、部署链路（CloudBase）

```bash
# 1) 引擎改动后，先同步到云函数副本，再从 cloud/ 目录部署
cp -rf quant/. cloud/functions/snapshot_py/quant/
cd cloud && tcb fn deploy snapshot_py      # 必须从 cloud/ 跑（cloudbaserc.json 所在）

# 2) 前端构建 + 静态托管
cd web && npm run build                    # 注意：不要 npm install
cd ../cloud && tcb hosting deploy ../web/dist quant -e <envId>
```

**踩坑记录**（血泪，别再犯）：
- `tcb fn deploy` 必须在 `cloud/` 目录执行，否则会打包整个 cwd 导致失败或静默跑旧码；
- 云函数内再调用长函数需显式 `callFunction({...}, {timeout: 60000})`，SDK 默认 15s 会静默超时；
- 云端 Python 3.7 需 `from __future__ import annotations`；时间戳用 `utcnow() + 8h`；
- 聚合文档**写回时必须合并保留旧字段**，否则每日结算会把 `replay` 等派生字段覆盖成 `null`。

## 六、数据边界（不虚构原则）

| 数据 | 可得性 |
|---|---|
| 腾讯 / 新浪 / 东财行情 | ✅ 可达 |
| 东财历史涨停池 | ⚠️ 仅约 15 个交易日 |
| 北向逐日持仓 / 净买卖 | ❌ 2024-08 起停发（仅剩前十大成交额，**无方向**，前端禁显净买/净卖） |
| 板块资金 / 人气 / 月线 | ❌ 需派生，不虚构数值 |

缺数据时输出**诚实占位**，绝不伪造链接或编造数值。
